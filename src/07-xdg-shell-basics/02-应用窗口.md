# 应用窗口

我们为了走到这一步已经剥了不知多少层（费了不知多少功夫），但时候到了：XDG 顶层窗口就是我们将最终用来显示应用窗口的接口。XDG 顶层窗口接口有许多用于管理应用窗口的请求和事件，包括处理最小化和最大化状态、设置窗口标题等等。我们会在后续章节中详细讨论它的每一部分，所以现在只关注基础内容。

基于上一章的知识，我们知道可以从一个 `wl_surface` 得到一个 `xdg_surface`，但这只构成了第一步：把一个表面纳入 XDG shell 的体系。下一步是把那个 XDG 表面变成一个 XDG 顶层窗口——一个“顶层”应用窗口，它因处于我们最终会用 XDG shell 创建的窗口与弹出菜单层级结构的顶层而得名。要创建其中一个，我们可以使用 `xdg_surface` 接口中相应的请求：

```xml
<request name="get_toplevel">
  <arg name="id" type="new_id" interface="xdg_toplevel"/>
</request>
```

这个新的 `xdg_toplevel` 接口为我们提供了许多请求和事件，用于管理应用窗口的生命周期。第 10 章会深入探讨这些内容，但我知道你已经迫不及待想让某个东西出现在屏幕上了。如果你遵循以下步骤，处理上一章讨论过的 XDG 表面的 `configure` 和 `ack_configure` 装置，并把一个 `wl_buffer` attach（附加）并提交到我们的 `wl_surface` 上，那么一个应用窗口就会出现，并把你的缓冲区内容呈现给用户。下一章提供了正是这样做的示例代码。它还利用了一个我们尚未覆盖的额外 XDG 顶层窗口请求：

```xml
<request name="set_title">
  <arg name="title" type="string"/>
</request>
```

这个应该相当不言自明。还有一个类似的、我们没有在示例代码中使用，但可能适合你的应用的请求：

```xml
<request name="set_app_id">
  <arg name="app_id" type="string"/>
</request>
```

标题通常显示在窗口装饰、任务栏等地方，而 app ID 则用于标识你的应用，或把你的窗口归为一组。你可以这样使用它们：把窗口标题设为 “Application windows — The Wayland Protocol — Firefox”，把你的 app ID 设为 “firefox”。

总而言之，以下步骤将带你从零开始把一个窗口显示在屏幕上：

1. 绑定到 `wl_compositor`，并用它创建一个 `wl_surface`。
2. 绑定到 `xdg_wm_base`，并用它和你的 `wl_surface` 创建一个 `xdg_surface`。
3. 用 `xdg_surface.get_toplevel` 从 `xdg_surface` 创建一个 `xdg_toplevel`。
4. 为 `xdg_surface` 配置一个监听器，并等待 `configure` 事件。
5. 绑定到你选定的缓冲区分配机制（例如 `wl_shm`）并分配一个共享缓冲区，然后把你的内容渲染到其中。
6. 使用 `wl_surface.attach` 把 `wl_buffer` attach 到 `wl_surface`。
7. 使用 `xdg_surface.ack_configure`，把来自 `configure` 的 serial 传给它，确认你已经准备好了一个合适的帧。
8. 发送一个 `wl_surface.commit` 请求。
