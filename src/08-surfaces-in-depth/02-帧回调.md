# 帧回调

更新表面最简单的方式，就是在它需要变化时直接重新渲染并附着新帧。比如，这种方式非常适合事件驱动的应用程序。用户按下一个键，文本框需要重新渲染，于是你可以立即重新渲染它、损伤相应的区域，并附着一个新的缓冲区，让它在下一帧被呈现。

然而，有些应用程序可能希望连续渲染帧。你可能在渲染电子游戏的帧、播放视频，或者渲染动画。你的显示器具有固有的*刷新率*，也就是它能够显示更新的最快速度（通常是一个类似 60 Hz、144 Hz 之类的数字）。以高于此的速度渲染帧毫无意义，而且这样做会浪费资源——CPU、GPU，甚至用户的电量。如果你在每次显示刷新之间发送若干帧，那么除最后一帧外都会被丢弃，白白渲染了。

此外，合成器甚至可能根本不想为你显示新的帧。你的应用程序可能处于屏幕之外、被最小化，或者被其他窗口遮挡；又或者只显示你应用程序的一小块缩略图，因此它们可能希望以更低的帧率渲染你，以节省资源。出于这个原因，在 Wayland 客户端中连续渲染帧的最佳方式，是让合成器告诉你它何时准备好接收新帧：也就是使用*帧回调*。

```xml
<interface name="wl_surface" version="4">
  <!-- ... -->

  <request name="frame">
    <arg name="callback" type="new_id" interface="wl_callback" />
  </request>

  <!-- ... -->
</interface>
```

这个请求会分配一个 `wl_callback` 对象，它的接口相当简单：

```xml
<interface name="wl_callback" version="1">
  <event name="done">
    <arg name="callback_data" type="uint" />
  </event>
</interface>
```

当你在一个表面上请求帧回调时，一旦合成器为该表面准备好接收新帧，它就会向该回调对象发送一个 `done` 事件。对于 `frame` 事件而言，`callback_data` 被设置为当前时间，单位为毫秒，其纪元未指定。你可以将它与你上一帧的时间进行比较，从而计算动画的进度或缩放输入事件。[^1]

现在，每一帧我们都会：

1. 销毁刚刚用过的帧回调。
2. 为下一帧请求一个新的回调。
3. 渲染并提交新帧。

将第三步拆解开来就是：

1. 用一个新偏移量更新我们的状态，利用自上一帧以来的时间以恒定的速率滚动。
2. 准备一个新的 `wl_buffer`，并为它渲染一帧。
3. 将这个新的 `wl_buffer` 附着到我们的表面上。
4. 损伤整个表面。
5. 提交表面。

第 3 步和第 4 步更新了该表面的*待定*状态，给它提供了新的缓冲区，并表明整个表面都已改变。第 5 步提交这个待定状态，将其应用到表面的当前状态，并在下一帧使用它。以原子方式应用这个新缓冲区，意味着我们绝不会显示出上一帧的一半，从而带来流畅无撕裂的体验。编译并运行更新后的客户端，亲自试一试吧！
