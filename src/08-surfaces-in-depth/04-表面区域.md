# 表面区域

我们已经使用过 `wl_compositor` 接口，通过 `wl_compositor.create_surface` 创建 `wl_surface`。不过请注意，它还有第二个请求：`create_region`。

```xml
<interface name="wl_compositor" version="4">
  <request name="create_surface">
    <arg name="id" type="new_id" interface="wl_surface" />
  </request>

  <request name="create_region">
    <arg name="id" type="new_id" interface="wl_region" />
  </request>
</interface>
```

`wl_region` 接口定义了一组矩形，它们共同构成一个任意形状的几何区域。它的请求允许你针对它所定义的几何形状执行按位运算——向其中添加矩形，或从中减去矩形。

```xml
<interface name="wl_region" version="1">
  <request name="destroy" type="destructor" />

  <request name="add">
    <arg name="x" type="int" />
    <arg name="y" type="int" />
    <arg name="width" type="int" />
    <arg name="height" type="int" />
  </request>

  <request name="subtract">
    <arg name="x" type="int" />
    <arg name="y" type="int" />
    <arg name="width" type="int" />
    <arg name="height" type="int" />
  </request>
</interface>
```

例如，要制作一个中间带洞的矩形，你可以：

1. 发送 `wl_compositor.create_region` 来分配一个 `wl_region` 对象。
2. 发送 `wl_region.add(0, 0, 512, 512)` 创建一个 512x512 的矩形。
3. 发送 `wl_region.subtract(128, 128, 256, 256)` 从该区域中央移除一个 256x256 的矩形。

这些区域也可以是彼此分离的；它不必是一个单一连续的多边形。一旦你创建了这样一个区域，就可以把它传入 `wl_surface` 接口，具体是通过 `set_opaque_region` 和 `set_input_region` 请求。

```xml
<interface name="wl_surface" version="4">
  <request name="set_opaque_region">
    <arg name="region" type="object" interface="wl_region" allow-null="true" />
  </request>

  <request name="set_input_region">
    <arg name="region" type="object" interface="wl_region" allow-null="true" />
  </request>
</interface>
```

不透明区域（opaque 区域）是给合成器的一个提示，指明你的表面的哪些部分被视为不透明。基于这一信息，合成器可以优化其渲染过程。例如，如果你的表面完全不透明，并且遮挡了它下面的另一个窗口，那么合成器就不会在你下面的窗口上浪费任何重绘的时间。默认情况下该区域为空，这意味着假定你的表面的任何部分都可能是透明的。这使默认情况成为效率最低但最正确的选择。

输入区域（input 区域）表明你的表面的哪些部分接受指针和触摸输入事件。例如，你可能在自己的表面下方绘制了投影，但发生在该区域内的输入事件应当被传递给位于你下方的客户端。又或者，如果你的窗口形状不寻常，你可以创建一个与之形状相符的输入区域。对于大多数表面类型而言，默认情况下你的整个表面都接受输入。

这两个请求都可以通过传入 null 而非 `wl_region` 对象来设置一个空区域。它们也都是双缓冲的——所以要发送一次 `wl_surface.commit` 才能让你的更改生效。一旦你用它发送过 `set_opaque_region` 或 `set_input_region` 请求，就可以销毁该 `wl_region` 对象以释放其资源。在这些请求发送之后再更新该区域，并不会更新表面的状态。
