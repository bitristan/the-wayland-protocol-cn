# 表面损伤

你可能已经注意到，在上一个示例中，当我们为表面提交一个新帧时，添加了这样一行代码：

```
wl_surface_damage_buffer(state->wl_surface, 0, 0, INT32_MAX, INT32_MAX);
```

如果注意到了，真是好眼力！这段代码*损伤*了我们的表面，向合成器表明它需要被重绘。这里我们损伤了整个表面（而且远远超出了它），但我们其实也可以只损伤它的一部分。

举例来说，假设你编写了一个 GUI 工具包，用户正在一个文本框中打字。那个文本框可能只占据窗口的一小部分，而每个新字符占据的部分更小。当用户按下一个键时，你可以只渲染追加到其正在书写文本之后的新字符，然后只损伤表面的那一部分。随后合成器可以只复制你表面的一小部分，这能显著加快速度——尤其是在嵌入式设备上。当你在字符之间闪烁光标时，你会希望为它的更新提交损伤；而当用户切换视图时，你很可能会损伤整个表面。这样一来，每个人都少做了工作，用户也会因为你改善了他的电池续航而感谢你。

**注意**：Wayland 协议提供了两个用于损伤表面的请求：`damage` 和 `damage_buffer`。前者实际上已被弃用，你应当只使用后者。它们之间的区别在于，`damage` 会考虑所有影响该表面的变换，例如旋转、缩放因子，以及缓冲区位置和裁剪。后者则改为相对于缓冲区来施加损伤，这通常更容易推理。
