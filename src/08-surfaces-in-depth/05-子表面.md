# 子表面

在核心 Wayland 协议 `wayland.xml` 中，只定义了一种[^1] 表面角色：子表面。它们相对于父表面拥有 X、Y 位置——该位置不必受父表面边界的约束——并且相对于其同级表面和父表面拥有 Z 序。

这项特性的一些用例包括：以原生像素格式播放视频表面，并在其上叠加 RGBA 用户界面或字幕；为主应用程序界面使用一个 OpenGL 表面，并用子表面以软件方式渲染窗口装饰；或者在不需在客户端重绘的情况下移动界面的某些部分。借助硬件平面（hardware plane），合成器甚至也可能无需为更新你的子表面而重绘任何内容。尤其在嵌入式系统上，当它契合你的用例时，这会特别有用。设计巧妙的应用程序可以利用子表面来获得极高的效率。

管理这些对象的接口是 `wl_subcompositor` 接口。`get_subsurface` 请求是通往子合成器（subcompositor）的主要入口：

```xml
<request name="get_subsurface">
  <arg name="id" type="new_id" interface="wl_subsurface" />
  <arg name="surface" type="object" interface="wl_surface" />
  <arg name="parent" type="object" interface="wl_surface" />
</request>
```

一旦你有了一个与某个 `wl_surface` 关联的 `wl_subsurface` 对象，该表面便成为其父表面的子表面。子表面自身还可以拥有子表面，从而在任何顶层窗口之下形成一棵有序的表面树。对这些子对象的操作通过 `wl_subsurface` 接口完成：

```xml
<request name="set_position">
  <arg name="x" type="int" summary="x coordinate in the parent surface"/>
  <arg name="y" type="int" summary="y coordinate in the parent surface"/>
</request>

<request name="place_above">
  <arg name="sibling" type="object" interface="wl_surface" />
</request>

<request name="place_below">
  <arg name="sibling" type="object" interface="wl_surface" />
</request>

<request name="set_sync" />
<request name="set_desync" />
```

子表面的 Z 序可以通过将它置于任一与其共享同一父表面的同级表面之上或之下，或置于父表面本身之上或之下，来加以改变。

对 `wl_subsurface` 各项属性的同步机制需要稍作解释。这些位置和 Z 序属性与父表面的生命周期同步。当为主表面发送 `wl_surface.commit` 请求时，其所有子表面的位置和 Z 序变更都会随之被应用。

然而，与该子表面关联的 `wl_surface` 状态——例如缓冲区的附加以及损伤的累积——不必与父表面的生命周期绑定。这正是 `set_sync` 和 `set_desync` 请求的用途。与父表面同步的子表面，会在父表面被提交时提交其全部状态。解除同步（desync）的表面则像别的表面一样管理自己的提交生命周期。

简而言之，sync 和 desync 请求是非缓冲的，会立即生效。位置和 Z 序请求则是缓冲的，且不受表面的 sync/desync 属性影响——它们始终随父表面一起提交。其余的表面状态（位于关联的 `wl_surface` 上）则依照该子表面的 sync/desync 状态进行提交。

[^1]: 不考虑已弃用的 `wl_shell` 接口。
