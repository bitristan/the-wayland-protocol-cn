# 引入事件循环

libwayland 自带一套事件循环实现，供 Wayland 服务端使用，但维护者已承认这属于一次设计上的越界。对客户端而言则没有这样的等价物。尽管如此，即便超出了本书的讨论范围，Wayland 服务端的事件循环也足够实用。

## Wayland 服务端事件循环

libwayland-server 创建的每个 `wl_display` 都有一个对应的 `wl_event_loop`，你可以通过 `wl_display_get_event_loop` 获取对它的引用。如果你在编写一个新的 Wayland 合成器，你很可能会想把它作为你唯一的事件循环。你可以用 `wl_event_loop_add_fd` 向它添加文件描述符，用 `wl_event_loop_add_timer` 添加定时器。它还通过 `wl_event_loop_add_signal` 处理信号，用起来相当方便。

把事件循环按你的喜好配置好，以监视你的合成器必须响应的所有事件之后，你就可以通过调用 `wl_display_run` 一次性处理事件并派发 Wayland 客户端，它会运行事件循环并阻塞，直到 display 终止（经由 `wl_display_terminate`）。大多数从一开始就以 Wayland 为本（而非从 X11 移植）构建的 Wayland 合成器都采用这种做法。

不过，你也可以亲自掌舵，把 Wayland display 纳入你自己的事件循环。`wl_display` 在内部使用该事件循环来处理客户端，你可以选择自行监视 Wayland 事件循环并按需派发它，也可以完全无视它、手动处理客户端更新。如果你希望让 Wayland 事件循环自己照顾自己，把它当作你自己事件循环的从属，你可以用 `wl_event_loop_get_fd` 获得一个可 [poll](https://pubs.opengroup.org/onlinepubs/009695399/functions/poll.html) 的文件描述符，然后在该文件描述符上出现活动时调用 `wl_event_loop_dispatch` 来处理事件。当你存在需要写入客户端的数据时，还需要调用 `wl_display_flush_clients`。

## Wayland 客户端事件循环

另一方面，libwayland-client 没有自己的事件循环。不过，由于通常只有一个文件描述符，没有它反而更容易管理。如果 Wayland 事件是你的程序唯一需要处理的那类事件，那么下面这个简单循环就足够了：

```c
while (wl_display_dispatch(display) != -1) {
    /* This space deliberately left blank */
}
```

然而，如果你的应用程序更为复杂，你可以按自己乐意的方式构建自己的事件循环，并用 `wl_display_get_fd` 获取 Wayland display 的文件描述符。在发生 `POLLIN` 事件时，调用 `wl_display_dispatch` 来处理传入事件。要冲刷传出的请求，请调用 `wl_display_flush`。
