# 接口与监听器

最后，我们终于抵达 libwayland 抽象的顶峰：接口与监听器。前面几章讨论过的那些概念——`wl_proxy` 和 `wl_resource`，以及各种原语——是存在于 libwayland 中的单一实现，它们的存在正是为了给这一层提供支持。当你把一个 XML 文件交给 wayland-scanner 处理时，它会生成*接口*和*监听器*，以及它们与底层线上协议接口之间的胶水代码，全都对应于高层协议中的每个接口。

回想一下，Wayland 连接上的每个参与者既可以接收也可以发送消息。客户端监听事件并发送请求，而服务端监听请求并发送事件。每一方都通过一个名字起得很贴切的 `wl_listener` 来监听对方的消息。下面是这个接口的一个例子：

```c
struct wl_surface_listener {
	/** surface enters an output */
	void (*enter)(void *data,
		      struct wl_surface *wl_surface,
		      struct wl_output *output);

	/** surface leaves an output */
	void (*leave)(void *data,
		      struct wl_surface *wl_surface,
		      struct wl_output *output);
};
```

这是 `wl_surface` 的一个客户端监听器。wayland-scanner 用来生成它的 XML 是：

```xml
<interface name="wl_surface" version="4">
  <event name="enter">
    <arg name="output"
      type="object"
      interface="wl_output"/>
  </event>

  <event name="leave">
    <arg name="output"
      type="object"
      interface="wl_output"/>
  </event>
  <!-- additional details omitted for brevity -->
</interface>
```

这些事件如何变成一个监听器接口，应该相当清楚了。每个函数指针都接收一份任意的用户数据、一个事件所指向的资源的引用，以及该事件的参数。我们可以像这样把一个监听器绑定到 `wl_surface` 上：

```c
static void wl_surface_enter(void *data,
        struct wl_surface *wl_surface, struct wl_output *output) {
    // ...
}

static void wl_surface_leave(void *data,
        struct wl_surface *wl_surface, struct wl_output *output) {
    // ...
}

static const struct wl_surface_listener surface_listener = {
    .enter = wl_surface_enter,
    .leave = wl_surface_leave,
};

// ...

struct wl_surface *surf;
wl_surface_add_listener(surf, &surface_listener, NULL);
```

`wl_surface` 接口还定义了客户端可以针对该表面发起的一些请求：

```xml
<interface name="wl_surface" version="4">
  <request name="attach">
    <arg name="buffer"
      type="object"
      interface="wl_buffer"
      allow-null="true"/>
    <arg name="x" type="int"/>
    <arg name="y" type="int"/>
  </request>
  <!-- additional details omitted for brevity -->
</interface>
```

wayland-scanner 会生成如下函数原型，以及负责将这条消息序列化的胶水代码。

```c
void wl_surface_attach(struct wl_surface *wl_surface,
    struct wl_buffer *buffer, int32_t x, int32_t y);
```

接口与监听器的服务端代码与之完全相同，只是方向相反——它为请求生成监听器，为事件生成胶水代码。当 libwayland 收到一条消息时，它会查找对象 ID 及其接口，再用它来解码消息的其余部分。然后它在这个对象上寻找监听器，并带上消息的参数来调用你的函数。

就是这么回事！我们经过了好几层抽象才走到这里，但你现在应该已经理解一个事件如何从你的服务端代码出发、变成线上的一条消息、被客户端理解、并最终分发到你的客户端代码。不过，还有一个问题没有回答。所有这一切都预设你已经拿到了 Wayland 对象的引用。那么，这些引用是从哪里来的呢？
