# 共享内存缓冲区

把像素从客户端传到合成器的最简单方式，也是唯一被写入 `wayland.xml` 的方式，就是 `wl_shm`——共享内存。简单地说，它允许你传递一个文件描述符，让合成器用 `MAP_SHARED` 进行 mmap，然后从这个池中共享出像素缓冲区。再加上一些简单的同步原语，以免大家为每个缓冲区争抢，你就得到了一个可行——而且可移植——的解决方案。

## 绑定 wl_shm

第 5.1 节讲解的注册表全局对象监听器会在 `wl_shm` 全局对象可用时通告它。绑定它相当直接。把第 5.1 节给出的示例加以扩展，就得到如下代码：

```
struct our_state {
    // ...
    struct wl_shm *shm;
    // ...
};

static void
registry_handle_global(void *data, struct wl_registry *registry,
		uint32_t name, const char *interface, uint32_t version)
{
    struct our_state *state = data;
    if (strcmp(interface, wl_shm_interface.name) == 0) {
        state->shm = wl_registry_bind(
            wl_registry, name, &wl_shm_interface, 1);
    }
}

int
main(int argc, char *argv[])
{
    struct our_state state = { 0 };
    // ...
    wl_registry_add_listener(registry, &registry_listener, &state);
    // ...
}
```

绑定之后，我们可以选择通过 `wl_shm_add_listener` 添加一个监听器。合成器会通过这个监听器通告它支持的像素格式。所有可能的像素格式完整列表见 `wayland.xml`。有两种格式是必须支持的：`ARGB8888` 和 `XRGB8888`，它们分别是带 alpha 通道和不带 alpha 通道的 24 位色。

## 分配共享内存池

结合 POSIX 的 `shm_open` 与随机文件名，可以用来创建适合此用途的文件，再用 `ftruncate` 把它调整到合适的大小。以下样板代码可在公有领域或 CC0 下自由使用：

```
#define _POSIX_C_SOURCE 200112L
#include <errno.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <time.h>
#include <unistd.h>

static void
randname(char *buf)
{
	struct timespec ts;
	clock_gettime(CLOCK_REALTIME, &ts);
	long r = ts.tv_nsec;
	for (int i = 0; i < 6; ++i) {
		buf[i] = 'A'+(r&15)+(r&16)*2;
		r >>= 5;
	}
}

static int
create_shm_file(void)
{
	int retries = 100;
	do {
		char name[] = "/wl_shm-XXXXXX";
		randname(name + sizeof(name) - 7);
		--retries;
		int fd = shm_open(name, O_RDWR | O_CREAT | O_EXCL, 0600);
		if (fd >= 0) {
			shm_unlink(name);
			return fd;
		}
	} while (retries > 0 && errno == EEXIST);
	return -1;
}

int
allocate_shm_file(size_t size)
{
	int fd = create_shm_file();
	if (fd < 0)
		return -1;
	int ret;
	do {
		ret = ftruncate(fd, size);
	} while (ret < 0 && errno == EINTR);
	if (ret < 0) {
		close(fd);
		return -1;
	}
	return fd;
}
```

但愿这段代码足够不言自明（说说而已，常被打脸）。有了它，客户端就能相当轻松地创建一个共享内存池。比方说，我们想显示一个 1920x1080 的窗口。双缓冲需要两个缓冲区，也就是 4,147,200 个像素。假设像素格式是 `WL_SHM_FORMAT_XRGB8888`，那么每个像素 4 字节，池的总大小就是 16,588,800 字节。按照第 5.1 节的说明从注册表绑定 `wl_shm` 全局对象，然后像下面这样创建一个能容纳这些缓冲区的 shm 池：

```
const int width = 1920, height = 1080;
const int stride = width * 4;
const int shm_pool_size = height * stride * 2;

int fd = allocate_shm_file(shm_pool_size);
uint8_t *pool_data = mmap(NULL, shm_pool_size,
    PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);

struct wl_shm *shm = ...; // Bound from registry
struct wl_shm_pool *pool = wl_shm_create_pool(shm, fd, shm_pool_size);
```

## 从池中创建缓冲区

等这个消息传到合成器，它也会对同一个文件描述符进行 `mmap`。不过 Wayland 是异步的，所以我们可以立即开始从这个池中分配缓冲区。既然我们为两个缓冲区分配了空间，就可以给每个分配一个索引，并把该索引转换成池中的字节偏移量。有了这些信息，我们就能创建一个 `wl_buffer`：

```
int index = 0;
int offset = height * stride * index;
struct wl_buffer *buffer = wl_shm_pool_create_buffer(pool, offset,
    width, height, stride, WL_SHM_FORMAT_XRGB8888);
```

现在我们也可以往这个缓冲区里写图像了。例如，把它设置为纯白色：

```
uint32_t *pixels = (uint32_t *)&pool_data[offset];
memset(pixels, 0, width * height * 4);
```

或者，来点更有意思的，这是一个棋盘格图案：

```
uint32_t *pixels = (uint32_t *)&pool_data[offset];
for (int y = 0; y < height; ++y) {
  for (int x = 0; x < width; ++x) {
    if ((x + y / 8 * 8) % 16 < 8) {
      pixels[y * width + x] = 0xFF666666;
    } else {
      pixels[y * width + x] = 0xFFEEEEEE;
    }
  }
}
```

舞台已经搭好，我们把缓冲区附加到表面上，把整个表面标记为损坏[^1]，然后提交：

```c
wl_surface_attach(surface, buffer, 0, 0);
wl_surface_damage(surface, 0, 0, UINT32_MAX, UINT32_MAX);
wl_surface_commit(surface);
```

如果你把所有这些刚学到的知识应用到亲自编写一个 Wayland 客户端上，那么到达这一步时，你可能会困惑于自己的缓冲区为什么没有显示在屏幕上。我们漏掉了关键的收尾步骤——为你的表面分配一个角色。

[^1]: “损坏”意为“该区域需要重绘”

## 服务端的 wl_shm

不过，在抵达那一步之前，服务端这部分值得一记。libwayland 提供了一些辅助函数，让 `wl_shm` 的使用更简单。要为你的 display 配置它，只需要下面这些：

```
int
wl_display_init_shm(struct wl_display *display);

uint32_t *
wl_display_add_shm_format(struct wl_display *display, uint32_t format);
```

前者创建全局对象并搭建好内部实现，后者添加一种受支持的像素格式（记得至少添加 ARGB8888 和 XRGB8888）。一旦客户端把缓冲区附加到它的某个表面上，你就可以把缓冲区资源传入 `wl_shm_buffer_get`，以获取一个 `wl_shm_buffer` 引用，并像下面这样使用它：

```
void
wl_shm_buffer_begin_access(struct wl_shm_buffer *buffer);

void
wl_shm_buffer_end_access(struct wl_shm_buffer *buffer);

void *
wl_shm_buffer_get_data(struct wl_shm_buffer *buffer);

int32_t
wl_shm_buffer_get_stride(struct wl_shm_buffer *buffer);

uint32_t
wl_shm_buffer_get_format(struct wl_shm_buffer *buffer);

int32_t
wl_shm_buffer_get_width(struct wl_shm_buffer *buffer);

int32_t
wl_shm_buffer_get_height(struct wl_shm_buffer *buffer);
```

如果你用 `begin_access` 和 `end_access` 来保护对缓冲区数据的访问，libwayland 会替你处理加锁。
