# 指针输入

借助 `wl_seat.get_pointer` 请求，客户端可以获得一个 `wl_pointer` 对象。每当用户移动指针、按下鼠标按键、使用滚轮等等时——只要指针位于你的某个表面之上——服务端就会向它发送事件。我们可以通过 `wl_pointer.enter` 事件来判断这一条件是否满足：

```xml
<event name="enter">
  <arg name="serial" type="uint" />
  <arg name="surface" type="object" interface="wl_surface" />
  <arg name="surface_x" type="fixed" />
  <arg name="surface_y" type="fixed" />
</event>
```

当指针移到我们的某个表面之上时，服务端会发送此事件，并同时指明被“进入”的表面，以及指针所处的表面局部坐标（自左上角算起）。这里的坐标用 “fixed” 类型表示，你可能还记得第 2.1 节里说过它表示一个 24.8 位定点精度数（`wl_fixed_to_double` 会把它转换为 C 的 `double` 类型）。

当指针移离你的表面时，对应的事件更简短：

```xml
<event name="leave">
  <arg name="serial" type="uint" />
  <arg name="surface" type="object" interface="wl_surface" />
</event>
```

一旦指针进入了你的表面，你就会开始收到针对它的额外事件，我们稍后会讨论。不过，你很可能首先要做的事是提供一个光标图像。过程如下：

1. 用 `wl_compositor` 创建一个新的 `wl_surface`。
2. 使用 `wl_pointer.set_cursor` 把该表面附加到指针上。
3. 给该表面附加一个光标图像 `wl_buffer` 并提交它。

这里唯一新引入的 API 是 `wl_pointer.set_cursor`:

```xml
<request name="set_cursor">
  <arg name="serial" type="uint" />
  <arg name="surface" type="object" interface="wl_surface" allow-null="true" />
  <arg name="hotspot_x" type="int" />
  <arg name="hotspot_y" type="int" />
</request>
```

这里的 `serial` 必须来自 `enter` 事件。`hotspot_x` 和 `hotspot_y` 参数指定“热点”在光标表面局部坐标系中的位置，也就是指针在光标图像内的有效位置（例如箭头尖端处）。另请注意，表面可以为 null——用它来完全隐藏光标。

如果你正在寻找好的光标图像来源，libwayland 附带了一个独立的 `wayland-cursor` 库，它可以从磁盘加载 X 光标主题并为它们创建 `wl_buffers`。详情见 `wayland-cursor.h`，或参见我们在第 9.5 节中对示例客户端的更新。

* 注意：wayland-cursor 包含了处理动态光标的代码，而动态光标在 1998 年就已经不酷了。我要是你，才不会去碰它。从来没有人抱怨过我的 Wayland 客户端不支持动态光标。*

在光标进入你的表面且你已附加了合适的光标之后，你就可以开始处理输入事件了。有 motion、button 和 axis 三类事件。

## 指针帧

服务端上单帧输入处理可能携带大量变化的信息——例如，轮询一次鼠标可能在一个数据包中返回更新后的位置和某个按键的释放。服务端把这些变化作为单独的 *Wayland* 事件发送，并用 “frame” 事件把它们归为一组。

```
<event name="frame"></event>
```

客户端应当在其收到 `wl_pointer` 事件时把它们全部累积起来，然后在收到 “frame” 事件后，将待处理的输入作为单个指针事件来处理。

## 移动事件

移动事件所用的坐标空间与 `enter` 事件相同，并且相当直接：

```xml
<event name="motion">
  <arg name="time" type="uint" />
  <arg name="surface_x" type="fixed" />
  <arg name="surface_y" type="fixed" />
</event>
```

像所有带时间戳的输入事件一样，`time` 值是与该输入事件关联的、单调递增的毫秒级精度时间戳。

## 按键事件

按键事件基本不言自明：

```xml
<enum name="button_state">
  <entry name="released" value="0" />
  <entry name="pressed" value="1" />
</enum>

<event name="button">
  <arg name="serial" type="uint" />
  <arg name="time" type="uint" />
  <arg name="button" type="uint" />
  <arg name="state" type="uint" enum="button_state" />
</event>
```

不过，`button` 参数值得额外解释一下。这个数字是一个平台相关的输入事件编码，不过要注意 FreeBSD 复用了 Linux 的取值。你可以在 `linux/input-event-codes.h` 中找到 Linux 的这些取值，其中最有用的大概是常量 `BTN_LEFT`、`BTN_RIGHT` 和 `BTN_MIDDLE`。还有更多，就留给你闲暇时自行翻阅那个头文件吧。

## 轴事件

轴事件用于滚动操作，比如转动滚轮或把它从左向右摇摆。最基本的形式如下：

```xml
<enum name="axis">
  <entry name="vertical_scroll" value="0" />
  <entry name="horizontal_scroll" value="1" />
</enum>

<event name="axis">
  <arg name="time" type="uint" />
  <arg name="axis" type="uint" enum="axis" />
  <arg name="value" type="fixed" />
</event>
```

然而，轴事件很复杂，这也是多年来 `wl_pointer` 接口中最受关注的部分。存在若干额外事件来提高轴事件的针对性：

```xml
<enum name="axis_source">
  <entry name="wheel" value="0" />
  <entry name="finger" value="1" />
  <entry name="continuous" value="2" />
  <entry name="wheel_tilt" value="3" />
</enum>

<event name="axis_source" since="5">
  <arg name="axis_source" type="uint" enum="axis_source" />
</event>
```

axis_source 事件告诉你被触发的是哪种轴——滚轮、还是触摸板上的手指、把摇摆键拨向一侧、或者某种更新奇的东西。这个事件很简单，但其余的就没那么简单了：

```xml
<event name="axis_stop" since="5">
  <arg name="time" type="uint" />
  <arg name="axis" type="uint" enum="axis" />
</event>

<event name="axis_discrete" since="5">
  <arg name="axis" type="uint" enum="axis" />
  <arg name="discrete" type="int" />
</event>
```

这两个事件的确切语义很复杂，如果你想利用它们，我建议仔细阅读 `wayland.xml` 中的概述。简而言之，`axis_discrete` 事件用于在任意尺度的轴事件与离散步进（例如滚轮的每一次“咔哒”代表轴值的一次离散变化）之间加以区分。`axis_stop` 事件表示一次离散的用户动作已经完成，用于处理发生在若干帧内的一次滚动事件。此后任何事件都应被解读为一次独立的动作。
