# 触摸输入

从表面上看，触摸屏输入相当简单，你的实现也可以做得很简单。然而，该协议为你提供了很大的深度，应用程序可以利用这些深度来提供更细致入微的触摸手势和反馈。

大多数触摸屏设备都支持*多点触控*（multitouch）：它们能够追踪屏幕上被触摸的多个位置。每一个这样的“触摸点”都会被分配一个 ID，该 ID 在当前所有处于活跃状态的屏幕触摸点中是唯一的，但如果你抬起手指再按下去，它可能会被复用。[^1]

与其他输入设备类似，你可以通过 `wl_seat.get_touch` 获取一个 `wl_touch` 资源，并在用完它之后发送一个“release”请求。

## 触摸帧

与指针一样，服务端上一帧（frame）的触摸处理可能携带许多变更的信息，但服务端会将这些变更作为离散的 Wayland 事件发送。`wl_touch.frame` 事件用于将这些事件归为一组。

```
<event name="frame"></event>
```

客户端应当在收到 `wl_touch` 事件时就累积它们，然后在收到“frame”事件时，把待处理的输入作为一个单一的触摸事件来处理。

## 按下与抬起

我们要看的首批事件是“down”和“up”，它们分别在你将手指按在设备上、以及将手指从设备上移开时被触发。

```
<event name="down">
  <arg name="serial" type="uint" />
  <arg name="time" type="uint" />
  <arg name="surface" type="object" interface="wl_surface" />
  <arg name="id" type="int" />
  <arg name="x" type="fixed" />
  <arg name="y" type="fixed" />
</event>

<event name="up">
  <arg name="serial" type="uint" />
  <arg name="time" type="uint" />
  <arg name="id" type="int" />
</event>
```

“x”和“y”坐标是定点（fixed-point）坐标，位于被触摸的表面的坐标空间中——该表面由“surface”参数给出。时间是单调递增的时间戳，其纪元（epoch）是任意的，单位为毫秒。[^2] 另请注意其中包含了一个 serial，它可以被包含在后续的请求中，以便将这些请求与该输入事件关联起来。

## 移动

在你收到带有特定触摸 ID 的“down”事件之后，你将开始收到描述该触摸点在设备上移动情况的移动事件。

```
<event name="motion">
  <arg name="time" type="uint" />
  <arg name="id" type="int" />
  <arg name="x" type="fixed" />
  <arg name="y" type="fixed" />
</event>
```

这里的“x”和“y”坐标位于“enter”事件所针对的那个表面的相对坐标空间中。

## 手势取消

触摸事件往往必须达到某个阈值，才会被识别为一个手势。例如，在屏幕上从左向右滑动，可能被 Wayland 合成器用来在应用程序之间切换。然而，只有当跨越了某个阈值之后——比如说，在一定时间内到达屏幕的中点——合成器才会将该行为识别为一个手势。

在达到该阈值之前，合成器会为被触摸的表面发送正常的触摸事件。一旦识别出手势，合成器就会发送一个“cancel”事件，让你知道合成器正在接管。

```
<event name="cancel"></event>
```

当你收到该事件时，所有活跃的触摸点都被取消。

## 形状与方向

一些高端触摸硬件能够确定更多关于用户与其交互方式的信息。对于使用合适硬件的用户，以及希望采用更高级的交互或触摸反馈的应用程序，协议提供了“shape”和“orientation”事件。

```
<event name="shape" since="6">
  <arg name="id" type="int" />
  <arg name="major" type="fixed" />
  <arg name="minor" type="fixed" />
</event>

<event name="orientation" since="6">
  <arg name="id" type="int" />
  <arg name="orientation" type="fixed" />
</event>
```

“shape”事件定义了一个对正在触摸屏幕的物体形状的椭圆近似，其长轴和短轴以被触摸表面的坐标空间中的单位来表示。orientation 事件则通过指定长轴与被触摸表面的 Y 轴之间的夹角（以度为单位）来旋转这个椭圆。

---

触摸是 Wayland 协议所支持的最后一类输入设备。掌握了这些知识，让我们来更新我们的示例代码。

[^1]: 重点在于“可能”——不要基于触摸点 ID 的重复使用做出任何假设。

[^2]: 这意味着，各个时间戳之间可以相互比较，从而得出事件之间的时间间隔，但它们无法与墙上时钟（wall-clock）时间相比较。
