# 键盘输入

有了对如何使用 XKB 的理解，让我们扩展 Wayland 代码，让它为我们提供可供其处理的按键事件。与获取 `wl_pointer` 资源的方式类似，我们可以使用 `wl_seat.get_keyboard` 请求，为一个能力包含 `WL_SEAT_CAPABILITY_KEYBOARD` 的 seat 创建 `wl_keyboard`。用完之后，你应该发送 “release” 请求：

```
<request name="release" type="destructor" since="3">
</request>
```

这会允许服务端清理与该键盘相关联的资源。

但究竟该怎么使用它呢？让我们从基础开始。

## 键盘映射

当你绑定到 `wl_keyboard` 时，服务端很可能发送的第一个事件就是 `keymap`。

```
<enum name="keymap_format">
  <entry name="no_keymap" value="0" />
  <entry name="xkb_v1" value="1" />
</enum>

<event name="keymap">
  <arg name="format" type="uint" enum="keymap_format" />
  <arg name="fd" type="fd" />
  <arg name="size" type="uint" />
</event>
```

提供 `keymap_format` 枚举，是为了以防我们将来为键盘映射想出某种新的格式，但在撰写本文时，XKB 键盘映射是服务端唯一可能发送的格式。

像这样的批量数据通过文件描述符传输。我们本可以简单地读取该文件描述符，但一般而言推荐改用 mmap 映射它。在 C 中，这看起来可能类似以下代码：

```
#include <sys/mman.h>
// ...

static void wl_keyboard_keymap(void *data, struct wl_keyboard *wl_keyboard,
        uint32_t format, int32_t fd, uint32_t size) {
    assert(format == WL_KEYBOARD_KEYMAP_FORMAT_XKB_V1);
    struct my_state *state = (struct my_state *)data;

    char *map_shm = mmap(NULL, size, PROT_READ, MAP_PRIVATE, fd, 0);
    assert(map_shm != MAP_FAILED);

    struct xkb_keymap *keymap = xkb_keymap_new_from_string(
        state->xkb_context, map_shm, XKB_KEYMAP_FORMAT_TEXT_V1,
        XKB_KEYMAP_COMPILE_NO_FLAGS);
    munmap(map_shm, size);
    close(fd);

    // ...do something with keymap...
}
```

一旦我们有了键盘映射，就可以为这个 `wl_keyboard` 解释后续的按键事件了。注意服务端可以在任何时候发送新的键盘映射，所有后续的按键事件都应当据此来解释。

## 键盘焦点

```
<event name="enter">
  <arg name="serial" type="uint" />
  <arg name="surface" type="object" interface="wl_surface" />
  <arg name="keys" type="array" />
</event>

<event name="leave">
  <arg name="serial" type="uint" />
  <arg name="surface" type="object" interface="wl_surface" />
</event>
```

如同 `wl_pointer` 的 “enter” 和 “leave” 事件在指针移动到你的表面上时发出一样，当某个表面获得键盘焦点时服务端发送 `wl_keyboard.enter`，当它失去焦点时发送 `wl_keyboard.leave`。许多应用会在这些情况下改变外观——例如，开始绘制一个闪烁的光标。

“enter” 事件还包含一个当前按下的键的数组。这是一个 32 位无符号整数数组，每个元素代表一个被按下按键的扫描码。

## 输入事件

一旦键盘进入了你的表面，你就可以期待开始接收输入事件。

```
<enum name="key_state">
  <entry name="released" value="0" />
  <entry name="pressed" value="1" />
</enum>

<event name="key">
  <arg name="serial" type="uint" />
  <arg name="time" type="uint" />
  <arg name="key" type="uint" />
  <arg name="state" type="uint" enum="key_state" />
</event>

<event name="modifiers">
  <arg name="serial" type="uint" />
  <arg name="mods_depressed" type="uint" />
  <arg name="mods_latched" type="uint" />
  <arg name="mods_locked" type="uint" />
  <arg name="group" type="uint" />
</event>
```

“key” 事件在用户按下或释放某个键时发送。像许多输入事件一样，它包含一个 serial，你可以用它把后续请求与这个输入事件关联起来。“key” 是被按下或释放的那个键的扫描码，而 “state” 是该键的按下或释放状态。

**重要**：该事件中的扫描码是 Linux evdev 扫描码。要把它转换成 XKB 扫描码，你必须给 evdev 扫描码加上 8。

修饰键事件包含一个类似的 serial，以及按下、暂锁和锁定修饰键的掩码，还有当前使用的输入组的索引。例如，当你按住 Shift 时，某个修饰键就处于按下状态。修饰键可以暂锁，比如在启用粘滞键的情况下按下 Shift——在下一次按下非修饰键之后它就会停止生效。而修饰键也可以锁定，比如当大写锁定被打开或关闭时。输入组用于在各种键盘布局之间切换，例如在 ISO 与 ANSI 布局之间切换，或用于更多与语言相关的特性。

修饰键的解释是依键盘映射而定的。你应当把它们两者都转发给 XKB 去处理。“modifiers” 事件的大多数实现都很直接：

```
static void wl_keyboard_modifiers(void *data, struct wl_keyboard *wl_keyboard,
        uint32_t serial, uint32_t depressed, uint32_t latched,
        uint32_t locked, uint32_t group) {
    struct my_state *state = (struct my_state *)data;
    xkb_state_update_mask(state->xkb_state,
        depressed, latched, locked, 0, 0, group);
}
```

## 按键重复

最后一个要考虑的事件是 “repeat_info” 事件：

```
<event name="repeat_info" since="4">
  <arg name="rate" type="int" />
  <arg name="delay" type="int" />
</event>
```

在 Wayland 中，客户端负责实现 “按键重复”——即只要你一直按住某个键不放，它就会持续输入字符的功能。这个事件用于告知客户端用户在按键重复设置方面的偏好。“delay” 是一个键在被按住多少毫秒之后按键重复才会启动，而 “rate” 则是直到该键被释放之前每秒重复的字符数。
