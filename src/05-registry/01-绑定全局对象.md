# 绑定全局对象

创建注册表对象后，服务端会为服务端上可用的每一个全局对象发出 `global` 事件。随后你就可以绑定到你所需的全局对象。

*绑定*是指取出一个已知对象并为其分配 ID 的过程。一旦客户端像这样绑定到注册表，服务端就会多次发出 `global` 事件，以通告它支持哪些接口。每个这样的全局对象都会被分配一个唯一的 `name`，形式为一个无符号整数。`interface` 字符串对应的是协议中所见的接口名称：上面 XML 中的 `wl_display` 就是这样一个名称的示例。版本号也在这里定义——关于接口版本的更多信息，参见附录 C。

要绑定到其中任何一个接口，我们使用 bind 请求，它的工作方式与我们绑定到 `wl_registry` 的那个神奇过程类似。例如，考虑下面这段线上协议交互：

```
C->S    00000001 000C0001 00000002            .... .... ....

S->C    00000002 001C0000 00000001 00000007   .... .... .... ....
        776C5f73 686d0000 00000001            wl_s hm.. ....
        [...]

C->S    00000002 00100000 00000001 00000003   .... .... .... ....
```

第一条消息与我们已经剖析过的那条完全相同。第二条是来自服务端的事件：对象 2（客户端在第一条消息中把 `wl_registry` 分配给了它）操作码 0（“global”），参数为 1、“wl_shm” 和 1——分别是这个全局对象的 name、接口和 version。客户端通过在对象 ID 2（`wl_registry::bind`）上调用操作码 0 来响应，并把对象 ID `3` 分配给全局对象 name `1`——即*绑定*到 `wl_shm` 全局对象。该对象未来的事件和请求由 `wl_shm` 协议定义，你可以在 `wayland.xml` 中找到它。

一旦创建了这个对象，你就可以利用它的接口来完成各种任务——就 `wl_shm` 而言，是在客户端与服务端之间管理共享内存。本书剩余的大部分内容都致力于讲解这些全局对象中每一个的用法。

有了这些信息，我们就可以编写第一个有用的 Wayland 客户端了：一个只是简单地打印出服务端上所有可用全局对象的程序。

```c
#include <stdint.h>
#include <stdio.h>
#include <wayland-client.h>

static void
registry_handle_global(void *data, struct wl_registry *registry,
		uint32_t name, const char *interface, uint32_t version)
{
	printf("interface: '%s', version: %d, name: %d\n",
			interface, version, name);
}

static void
registry_handle_global_remove(void *data, struct wl_registry *registry,
		uint32_t name)
{
	// This space deliberately left blank
}

static const struct wl_registry_listener
registry_listener = {
	.global = registry_handle_global,
	.global_remove = registry_handle_global_remove,
};

int
main(int argc, char *argv[])
{
	struct wl_display *display = wl_display_connect(NULL);
	struct wl_registry *registry = wl_display_get_registry(display);
	wl_registry_add_listener(registry, &registry_listener, NULL);
	wl_display_roundtrip(display);
	return 0;
}
```

解读这个程序时，请随意参考前面的章节。我们连接到 display（第 4.1 节），获取注册表（本章），为它添加一个监听器（第 3.4 节），然后进行往返（round-trip），通过打印此合成器上可用的全局对象来处理 global 事件。你自己动手试试：

```c
$ cc -o globals -lwayland-client globals.c
```

**注意**：本章是我们最后一次以十六进制形式展示线上协议转储，而且这大概也是你今后最后一次见到它们了。跟踪你的 Wayland 客户端或服务端的一个更好的方法，是在运行程序之前把环境中的 `WAYLAND_DEBUG` 变量设置为 `1`。现在就用 “globals” 程序试一下吧！
