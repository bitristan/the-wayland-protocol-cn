# 注册全局对象

用 libwayland-server 注册全局对象的方式略有不同。当你用 wayland-scanner 生成 “server-code”（服务端代码）时，它会创建接口（类似于监听器）以及用于发送事件的胶水代码。第一项任务是注册全局对象，并提供一个函数，以便在全局对象被绑定时装配起一个*资源*[^1]。用代码来表示，结果大概长这样：

```c
static void
wl_output_handle_bind(struct wl_client *client, void *data,
    uint32_t version, uint32_t id)
{
    struct my_state *state = data;
    // TODO
}

int
main(int argc, char *argv[])
{
    struct wl_display *display = wl_display_create();
    struct my_state state = { ... };
    // ...
    wl_global_create(wl_display, &wl_output_interface,
        1, &state, wl_output_handle_bind);
    // ...
}
```

如果你把这段代码，比如，补进第 4.1 节的服务端示例中，你就会让一个 `wl_output` 全局对象对我们上次编写的 “globals” 程序可见[^2]。不过，任何绑定到这个全局对象的尝试都会撞上我们的 TODO。为了填补它，我们还需要为 `wl_output` 接口提供一个*实现*。

```c
static void
wl_output_handle_resource_destroy(struct wl_resource *resource)
{
    struct my_output *client_output = wl_resource_get_user_data(resource);

    // TODO: Clean up resource

    remove_to_list(client_output->state->client_outputs, client_output);
}

static void
wl_output_handle_release(struct wl_client *client, struct wl_resource *resource)
{
    wl_resource_destroy(resource);
}

static const struct wl_output_interface
wl_output_implementation = {
    .release = wl_output_handle_release,
};

static void
wl_output_handle_bind(struct wl_client *client, void *data,
    uint32_t version, uint32_t id)
{
    struct my_state *state = data;

    struct my_output *client_output = calloc(1, sizeof(struct client_output));

    struct wl_resource *resource = wl_resource_create(
        client, &wl_output_interface, wl_output_interface.version, id);

    wl_resource_set_implementation(resource, &wl_output_implementation,
        client_output, wl_output_handle_resource_destroy);

    client_output->resource = resource;
    client_output->state = state;

    // TODO: Send geometry event, et al

    add_to_list(state->client_outputs, client_output);
}
```

要消化的东西很多，所以我们一小块一小块地来解释。在最底部，我们扩展了 “bind” 处理函数，创建一个 `wl_resource` 来跟踪这个对象在服务端一侧的状态（使用客户端分配的那个 ID）。在此过程中，我们把指向接口实现的指针——`wl_output_implementation`，本文件中的一个常量静态结构体——传给 `wl_resource_create`。该类型（`struct wl_output_interface`）由 `wayland-scanner` 生成，为此接口所支持的每一个请求包含一个函数指针。我们也借此机会分配一个小容器，用来存储 libwayland 不替我们处理的任何额外状态，其具体性质因协议而异。

**注意：** 这里有两个不同的东西共用了同一个名称：`struct wl_output_interface` 是接口的一个实例，而 `wl_output_interface` 是由 `wayland-scanner` 生成的一个全局常量变量，其中包含与该实现相关的元数据（例如上面例子中使用的 version）。

我们的 `wl_output_handle_release` 函数会在客户端发送 `release` 请求时被调用，表明它不再需要这个资源——于是我们销毁它。这又会触发 `wl_output_handle_resource_destroy` 函数，稍后我们会扩展它，以释放我们先前为其分配的任何状态。此函数也作为析构器被传入 `wl_resource_create`，如果客户端没有显式发送 `release` 请求就终止了，它就会被调用。

我们代码中另一个剩下的 “TODO” 是发送 “name” 事件，以及其他几个事件。如果我们查阅一下 `wayland.xml`，就会在接口上看到这个事件：

```xml
<event name="geometry">
  <description summary="properties of the output">
The geometry event describes geometric properties of the output.
The event is sent when binding to the output object and whenever
any of the properties change.

The physical size can be set to zero if it doesn't make sense for this
output (e.g. for projectors or virtual outputs).
  </description>
  <arg name="x" type="int" />
  <arg name="y" type="int" />
  <arg name="physical_width" type="int" />
  <arg name="physical_height" type="int" />
  <arg name="subpixel" type="int" enum="subpixel" />
  <arg name="make" type="string" />
  <arg name="model" type="string" />
  <arg name="transform" type="int" enum="transform" />
</event>
```

看来在 output 被绑定时发送这个事件是我们的职责。要加上它很容易：

```c
static void
wl_output_handle_bind(struct wl_client *client, void *data,
    uint32_t version, uint32_t id)
{
    struct my_state *state = data;

    struct my_output *client_output = calloc(1, sizeof(struct client_output));

    struct wl_resource *resource = wl_resource_create(
        client, &wl_output_implementation, wl_output_interface.version, id);

    wl_resource_set_implementation(resource, wl_output_implementation,
        client_output, wl_output_handle_resource_destroy);

    client_output->resource = resource;
    client_output->state = state;

    wl_output_send_geometry(resource, 0, 0, 1920, 1080,
        WL_OUTPUT_SUBPIXEL_UNKNOWN, "Foobar, Inc",
        "Fancy Monitor 9001 4K HD 120 FPS Noscope",
        WL_OUTPUT_TRANSFORM_NORMAL);

    add_to_list(state->client_outputs, client_output);
}
```

**注意**：这里展示 `wl_output::geometry` 只是出于说明目的，但在实践中它的使用有一些特殊的注意事项。在你的客户端或服务端中实现这个事件之前，请先审阅协议 XML。

[^1]: 资源代表每个客户端对某个对象的实例在服务端一侧的状态。

[^2]: 如果你对更健壮的东西感兴趣，Weston 项目提供了一个我们 “globals” 程序的略为精巧的版本，叫做 `weston-info`。
