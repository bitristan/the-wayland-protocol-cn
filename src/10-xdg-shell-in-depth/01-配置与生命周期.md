# 配置与生命周期

此前，我们创建了一个尺寸由我们自己选定的窗口：640x480。然而，合成器往往对窗口应当采用什么尺寸有自己的看法，而我们可能也想传达自己的偏好。若不能妥善处理这一点，通常会导致不理想的行为，比如合成器正试图告诉你把表面调小一些，结果却把你的窗口部分裁掉了。

合成器还可以向应用提供关于其展示上下文的额外线索。它可以让你知道应用是被最大化了还是处于全屏、是贴靠在其他窗口或显示器边缘的一侧或多侧、是获得焦点还是空闲，等等。由于 `wl_surface` 被用于以原子方式将表面的变更从客户端传达到服务端，`xdg_surface` 接口提供了下面这两条消息，用于让合成器提出变更建议、让客户端确认这些变更：

```xml
<request name="ack_configure">
  <arg name="serial" type="uint" />
</request>

<event name="configure">
  <arg name="serial" type="uint" />
</event>
```

单看这两条消息，它们几乎不携带什么含义。不过，`xdg_surface` 的每个子类（`xdg_toplevel` 和 `xdg_popup`）都有额外的事件，服务端可以在 “configure” 之前发送这些事件，以落实我们前面提到的每一项建议。服务端会把这些状态全部发送出去：已最大化、已获得焦点、建议的尺寸；然后再发送一个带有 serial 的 `configure` 事件。当客户端采用了与这些建议一致的状态后，它会发送一个带有相同 serial 的 `ack_configure` 请求来表示这一点。在随后对相关联的 `wl_surface` 进行一次提交之后，合成器便会认为该状态是一致的。

## XDG 顶层窗口生命周期

我们第 7 章里的示例代码可以正常工作，但它目前还不是桌面上的良好公民。它不会采用合成器建议的尺寸，而且如果用户尝试关闭窗口，它也不会消失。要响应这些由合成器提供的事件，涉及两个 Wayland 事件：`configure` 和 `close`。

```xml
<event name="configure">
  <arg name="width" type="int"/>
  <arg name="height" type="int"/>
  <arg name="states" type="array"/>
</event>

<event name="close" />
```

width 和 height 是合成器为该窗口首选的尺寸[^1]，而 states 是下列取值构成的数组：

```xml
<enum name="state">
  <entry name="maximized" />
  <entry name="fullscreen" />
  <entry name="resizing" />
  <entry name="activated" />
  <entry name="tiled_left" />
  <entry name="tiled_right" />
  <entry name="tiled_top" />
  <entry name="tiled_bottom" />
</enum>
```

close 事件可以忽略，一个典型的原因是向用户显示一个确认，以便保存尚未保存的工作。我们第 7 章的示例代码可以相当轻松地更新以支持这些事件：

## 请求状态变更

客户端也可以请求合成器把自己置于上述某个状态中，或者对窗口的尺寸施加约束。

```xml
<request name="set_max_size">
  <arg name="width" type="int"/>
  <arg name="height" type="int"/>
</request>

<request name="set_min_size">
  <arg name="width" type="int"/>
  <arg name="height" type="int"/>
</request>

<request name="set_maximized" />

<request name="unset_maximized" />

<request name="set_fullscreen" />
  <arg name="output"
    type="object"
    interface="wl_output"
    allow-null="true"/>
</request>

<request name="unset_fullscreen" />

<request name="set_minimized" />
```

合成器通过发送一个对应的 configure 事件来表示它对这些请求的确认。

[^1]: 这会考虑客户端通过 `set_window_geometry` 请求发送的窗口几何信息。建议的尺寸只包含窗口几何所表示的空间。
