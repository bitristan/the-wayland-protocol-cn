# 弹出窗口

在设计使用应用窗口的软件时，有许多场景会出于各种目的用到更小的次要表面。一些例子包括：右键时出现的上下文菜单、用于从若干选项中选取某个值的下拉框、鼠标悬停在某个 UI 元素上时显示的情境提示，以及窗口顶部和底部的菜单与工具栏。这些窗口常常会层层嵌套，例如沿着 “File → Recent Documents → Example.odt” 这样的路径打开。

对于 Wayland，XDG shell 提供了管理这些窗口的机制：弹出窗口。前面我们看过 `xdg_surface` 用于创建顶层应用窗口的 “`get_toplevel`” 请求。而对于弹出窗口，则改用 “`get_popup`” 请求。

```xml
<request name="get_popup">
  <arg name="id" type="new_id" interface="xdg_popup"/>
  <arg name="parent" type="object" interface="xdg_surface" allow-null="true"/>
  <arg name="positioner" type="object" interface="xdg_positioner"/>
</request>
```

第一个和第二个参数的含义相当显而易见，但第三个参数引入了一个新概念：定位器。顾名思义，定位器的作用就是为新弹出窗口*定位*。它用于让合成器借助自己掌握的特权信息来参与弹出窗口的定位，例如避免让弹出窗口延伸到显示器边缘之外。我们将在第 10.4 节讨论定位器；眼下你只需创建一个定位器并把它传进去、不做任何进一步配置，就能借助相应的 `xdg_wm_base` 请求获得相当合理的默认行为：

```xml
<request name="create_positioner">
  <arg name="id" type="new_id" interface="xdg_positioner"/>
</request>
```

因此，简而言之，我们可以：

1. 创建一个新的 `wl_surface`
2. 为它获取一个 `xdg_surface`
3. 创建一个新的 `xdg_positioner`，把它的配置留到第 10.4 节
4. 从我们的 XDG 表面和 XDG 定位器创建一个 `xdg_popup`，并把它的父窗口指定为我们之前创建的 `xdg_toplevel`。

然后我们就可以用前面讨论过的同样生命周期，为弹出窗口表面渲染并附加缓冲区。我们还能使用一些其他专属于弹出窗口的特性。

## 配置

和 XDG 顶层窗口的 configure 事件一样，合成器有一个事件，可用来建议你的弹出窗口应当采用的尺寸。不过，与顶层窗口不同的是，它还会附带一个定位事件，把弹出窗口相对于其父表面的位置告知客户端。

```xml
<event name="configure">
  <arg name="x" type="int"
 summary="x position relative to parent surface window geometry"/>
  <arg name="y" type="int"
 summary="y position relative to parent surface window geometry"/>
  <arg name="width" type="int" summary="window geometry width"/>
  <arg name="height" type="int" summary="window geometry height"/>
</event>
```

客户端可以用 XDG 定位器来影响这些取值，这将在第 10.4 节讨论。

## 弹出窗口抓取

弹出窗口表面常常希望 “抓取”（grab）所有输入，例如让用户用方向键选择不同的菜单项。这通过 grab 请求来实现：

```xml
<request name="grab">
  <arg name="seat" type="object" interface="wl_seat" />
  <arg name="serial" type="uint" />
</request>
```

发起这个请求的前提是已经收到了一个符合条件的输入事件，比如一次右键点击。该输入事件中的 serial 应当被用于这个请求。这些语义在第 9 章中有详细讨论。合成器之后可以取消这次抓取，例如当用户按下 escape 或点击你的弹出窗口外部时。

## 关闭

在合成器关闭你的弹出窗口的这些情形下，比如按下 escape 键时，会发送下面这个事件：

```xml
<event name="popup_done" />
```

为避免竞态条件，合成器会把弹出窗口结构保留在内存中，即便在它们被关闭之后也会处理针对它们的请求。关于对象生命周期和竞态条件的更多细节，参见第 2.4 节。

## 销毁弹出窗口

由客户端发起的弹出窗口销毁相当直接：

```xml
<request name="destroy" type="destructor" />
```

不过有一个细节值得一提：你必须自上而下地销毁所有弹出窗口。在任何时刻，你唯一能销毁的就是最顶层的那个。如果你不这么做，就会因协议错误而断开连接。
